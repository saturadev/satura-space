Publishing a web game

The same path on every platform: build for the web, package it the way the platform wants, upload, test on the platform, then send it for review or release it. Some steps can run from the terminal or an agent; signing in and the final submit stay with you.

The path

StepWhat happens
1. Pick the platformThe platform decides the SDK, the ad rules and the package format, so pick it first. See Where each platform takes builds.
2. Integrate its SDKLoading, gameplay and ad events through that platform's SDK, or through one cross-platform SDK. The Monetization plugin covers how.
3. Build for the webA WebGL build with settings that suit the platform's host. See Unity for the web.
4. PackageUsually a zip with index.html at its root, plus any config file the platform asks for.
5. UploadFrom a CLI, an API, an MCP server or the platform's web console, depending on the platform.
6. Test on the platformA preview link or QA tool runs the game as players will see it, with the real SDK. Ads and saves are only real there.
7. Review or releaseCurated portals review every game and many updates. Open stores release when you say so.

Three kinds of upload

  • Command line or API. An agent can push a build and get a link back. You sign in once, in your own terminal or browser, and the credentials stay on your computer.
  • MCP server. The platform's own server gives an agent tools to create the game page, upload builds and covers, and read review feedback. You allow the connection in your browser.
  • Web console only. The agent prepares the zip and the texts, you upload them in the platform's console.

Platforms add APIs over time. Before deciding a platform is console-only, check its current developer docs.

What always stays with you

  • Accounts and sign-in. Developer accounts, tax and payout forms, and every login. An agent never signs in for you and never keeps your keys in the project.
  • Submitting and releasing. Sending a game to review, pushing a version to production or updating a live game reaches real players. An agent prepares it and waits for your yes.
  • Store page materials. Title, description, icon, covers and screenshots. An agent can draft them; the platform's rules on sizes and content are on its own pages.

Before any upload

  • The game starts quickly and reaches play without a long menu.
  • It works with mouse and keyboard, and with touch on phones if the platform shows it there.
  • It fills its frame at every size and orientation the platform uses.
  • Progress survives a page reload, or the game says that it won't.
  • No external requests, links out or other ad systems unless the platform allows them.
  • No errors in the browser console.
Principles checked 2026-11-26. Limits, revenue shares, SDK versions and commands change, so they are not copied here: every platform fact links to its owner's page. Read that page before you act on it.
